# Deploying angelinale.dev

## Why deployment needs a root sync

The active app source is in `ver2/`. The GitHub Actions workflow at `.github/workflows/deploy-pages.yml` builds that app and uploads `ver2/dist`.

The live custom domain has also been served from the repository root. A successful Actions run alone did not update the site: the root `index.html` still referenced the previous bundles. The fix was to publish the same `ver2` build at the root, where the live Pages source could read it. Recent successful deployment commit: `247fe90f` (`Publish ver2 build at Pages root`).

Until the Pages source is confirmed to use GitHub Actions exclusively, update both `ver2/` and the root deploy files for each release.

## Release steps

1. Make app and asset changes in `ver2/`. Put app photos in `ver2/photos/` and keep `ver2/public/CNAME` set to `angelinale.dev`.
2. Build the production app:

   ```sh
   cd ver2
   npm run build
   cd ..
   ```

3. Sync the generated app to the repository-root Pages site:
   - Copy the current `ver2/dist/assets/index-*.js` and `index-*.css` bundles to root `assets/`.
   - Update root `index.html` to reference the exact JS and CSS filenames listed by `ver2/dist/index.html`.
   - Preserve the root favicon link (`/assets/favicon.ico`). The current Vite index template does not emit that link.
   - Copy required files from `ver2/dist/photos/` into root `photos/`.
   - Keep root `CNAME` set to `angelinale.dev`.
4. Check the artifacts before committing:
   - Root `index.html` references files that exist in root `assets/`.
   - The JS/CSS hashes in root `index.html` match `ver2/dist/index.html`.
   - Photos used by the app exist in root `photos/`.
   - Both `CNAME` files contain `angelinale.dev`.
   - Run `git diff --check` and inspect `git status`.
5. Commit and push to `main`. GitHub Actions will build/deploy `ver2/dist`; the root changes update the branch-root Pages source.
6. Wait for the Pages workflow and branch deployment to finish. Verify `https://angelinale.dev/` uses the new asset hashes and check the changed page in a fresh browser session. If the hashes are old, compare the live HTML with repository-root `index.html`; do not assume a green Actions run updated the branch-root site.

Do not commit `ver2/node_modules/.vite/` cache files. `ver2/dist/photos/` is generated by the build; the source photos belong in `ver2/photos/`.
